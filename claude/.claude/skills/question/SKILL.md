### Workflow: Direct Technical Answer

1. Read-only. Zero file or code mutations, even if the fix looks obvious. Offer the change in one line at the end instead.
2. Don't run checks, tests or builds unless asked. Reading files and searching are fine.
3. Ground the answer in the actual code and config: read before you claim. If you didn't verify something, say so.
4. Give a verdict. If the idea is bad, open with that and why, then the alternative. Never soften it.
